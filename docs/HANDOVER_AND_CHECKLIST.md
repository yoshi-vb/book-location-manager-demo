## 2. 既知の制約と未検証事項（正直な区分け）

実装および自動テストで確認済みの事項と、実機・実運用環境での確認が必要な事項を以下の通り明確に区別します。

1. **業務用iPhone（Edge）でのカメラ起動にはHTTPSまたはlocalhostが必要（iOS WebKitの仕様制約）**
   * **理由**: iOS上のすべてのブラウザ（Safari / Edge / Chrome）はAppleのセキュリティポリシーにより、`file://` や非暗号化の `http://192.168.x.x` では `navigator.mediaDevices.getUserMedia`（リアルタイムカメラ映像取得）をブロックします。
   * **対応策**: 実機カメラのリアルタイム連続スキャンを使う場合は、GitHub Pages等のHTTPS環境へプログラムのみを配置（※承認後に実施）するか、ローカルHTTPS/トンネル経由でアクセスしてください。また、HTTPSが使えない環境でも、`<input type="file" capture="environment">` を用いた「📸 奥付写真を選択してOCR」や「iOS標準テキスト認識入力」「手動検索」は制限なく動作します。
2. **現物の紙質・照明・縦書きフォントに対するブラウザ内OCR（Tesseract.js）の実測精度**
   * **未検証の理由**: 開発段階では現物のカメラ映像ではなく模擬OCRテキストと静止画で検証しているため、実際の書庫の照明環境や湾曲した紙面での認識速度・精度は実機テストでの確認が必要です。
   * **対応策**: OCRの認識精度が低い場合でも誤って自動確定せず、「手動確認が必要」と警告を出して部分一致候補を表示し、ワンタップで手動検索へ切り替えられる安全設計としています。
3. **既存の蔵書管理システムとの直接接続は未実装（仕様未確認のため）**
   * 要件に従い、既存システムへの自動接続や直接DB更新は行わず、安全な「別ファイルとしてのCSV入出力」に限定しています。
4. **日高倉庫への正式な入出庫申請・集荷依頼は手動手続きが必要**
   * 本アプリは「箱番号の採番・重複チェック」「図書と箱の紐付け記録」「所在を『外部倉庫（日高）＋管理番号』へ更新」「別紙2-3転記用データの作成」を行いますが、倉庫会社への実際の発注・申請手続きを自動送信するものではありません。

### 保守・カスタマイズのポイント（後任者の方へ）
1. **定型書架リストや部署コードを増やしたい場合**
   * `index.html` 内の `<select id="mobileHqPresetSelect">` に `<option>` を追加するだけで、iPhone側の定型書架プルダウンに反映されます。
   * 外部倉庫の「部・Gコード」は特定の部署コードに固定していないため、組織改編で新しい部署コード（例：`2101` や `DX01`）が増えてもプログラム修正なしでそのまま採番・チェックが可能です。
2. **既存台帳の標準項目を追加・変更したい場合**
   * `js/core_logic.js` 先頭の `STANDARD_FIELDS` 配列に項目定義と別名リスト（`aliases`）を追加すると、CSV取込時の列マッピング画面とCSV出力処理に自動的に反映されます。
3. **デモデータを再生成・変更したい場合**
   * `generate_demo_data.py` を編集して `python generate_demo_data.py` を実行すると、`data/demo_books.csv`, `data/demo_books.json`, `js/demo_data.js` の3ファイルが一括更新されます。
   * 変更後は必ず `python tests/test_suite.py` を実行し、全テストが `OK` になることを確認してください。
4. **GitHub Pages等で公開・社内共有する際の厳守事項**
   * `.gitignore` により `production_data/` や `*production*.csv` 等は除外されていますが、`git add` する前に必ず `git status` を確認し、**実データ（本番の蔵書CSV、変更履歴、撮影した奥付写真）がステージングに含まれていないこと**を確認してください。
