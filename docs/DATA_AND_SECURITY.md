# データ項目定義・バックアップ復元手順・外部通信一覧

## 1. 標準データ項目定義（仮の標準11項目）

> **注意**: 以下の項目構成は開発・検証用の標準モデルであり、既存台帳の確定仕様ではありません。実データのCSV取込時には、画面上の「列の対応付け（カラムマッピング）」機能によって任意の列名と以下の標準項目を紐付けることができます。

| 項番 | 内部キー (`key`) | 標準項目名（日本語） | 必須 | 主キー | 内容・形式・検証ルール |
| :---: | :--- | :--- | :---: | :---: | :--- |
| 1 | `book_id` | **図書登録番号** | **必須** | **〇** | 個々の現物を一意に識別する番号（例：`BK-00001`, `00120`）。重複不可。先頭ゼロを含む文字列も保持。 |
| 2 | `isbn` | **ISBN** | 任意 | - | ISBN-13（例：`978-4-478-11948-8`）または旧規格 ISBN-10（例：`4-535-51343-0`）。未登録（社内規程集・非売品等）も許容。チェックディジット検証を行うが、同一ISBNの複本が存在し得るため主キーにはしない。 |
| 3 | `title` | **書名** | **必須** | - | 書籍のタイトル（副題含む）。全角・半角の違いは検索・照合時にNFKC正規化して吸収。 |
| 4 | `author` | **著者・編者** | 任意 | - | 著者名・監修者名・編者名（未登録許容）。 |
| 5 | `publisher` | **出版社** | 任意 | - | 発行所・発売元（未登録許容）。 |
| 6 | `pub_year` | **発行年** | 任意 | - | 西暦4桁（例：`2025`）。 |
| 7 | `edition` | **版・巻号** | 任意 | - | 初版、第3刷、新版第1刷、2024年版（第4巻）など。同一書名・同一ISBNの識別に使用。 |
| 8 | `department` | **所管部署** | 任意 | - | 保有・管理する部署名（例：`1101: デジタル推進室`）。 |
| 9 | `location` | **現在の保管場所** | 任意 | - | 本部内の書架名、または外部倉庫発送時は `外部倉庫（日高）{箱管理番号}`。 |
| 10 | `box_number` | **外部倉庫の箱管理番号** | 任意 | - | 日高倉庫の文書箱番号。形式は `部室G-年度2桁-通し番号4桁BOK`（例：`1101-26-0001BOK`）。仮番号は不可。 |
| 11 | `notes` | **備考** | 任意 | - | 補足メモや管理上の注記。 |

### 別紙2-3 転記用データの出力項目定義
外部倉庫（日高倉庫）の箱管理番号ごとに集計して出力される転記用CSVの項目は以下のとおりです（※正式様式の現物そのものではなく、正式様式へ転記するためのデータです）。

| 出力列名 | 固定値／生成ルール |
| :--- | :--- |
| **箱管理番号** | `1101-26-0001BOK` 形式の箱番号 |
| **文書等種類** | 固定値：`"文書"` |
| **保存期限** | 固定値：`"永久"` |
| **保存期限日付値** | 固定値：`"2999/12/31"` |
| **名称（100文字以内）** | `"図書（{部署名}）計{冊数}冊：{主な書名1}、{主な書名2}…"` の形式で生成し、100文字を超える場合は末尾を `"…他"` として厳密に100文字以内に収める |
| **名称文字数** | 生成された名称の文字数（最大100） |
| **冊数** | その箱に入っている図書の合計冊数 |
| **対象部署** | 箱内の図書の所管部署一覧 |
| **格納図書登録番号一覧** | 箱内の図書登録番号（カンマ区切り） |

## 2. 端末内保存（LocalStorage）の仕様とバックアップ・復元手順

### 端末内に保存される内容・キーの分離・保存期間・消去方法
ブラウザの `localStorage` に以下の5つのキーでデータを保存します。**デモデータと本番データはキー自体が分離**されており、混ざりません。

| LocalStorage キー名 | 保存される内容 | 保存期間 | 消去方法 |
| :--- | :--- | :--- | :--- |
| `blm_active_data_mode_v1` | 現在表示中のモード（`"DEMO"` または `"PRODUCTION"`） | 無期限（手動消去まで） | PCモード「5. 変更履歴・バックアップ」タブの「🗑️ ブラウザ内保存データを全消去」ボタン |
| `blm_demo_state_v1` | デモデータ（架空蔵書リスト）の編集状態 | 無期限（手動消去まで） | 画面上部の「デモデータに戻す」または「全消去」ボタン |
| `blm_prod_state_v1` | CSV取込した本番用蔵書リストの状態 | 無期限（手動消去まで） | 「🗑️ ブラウザ内保存データを全消去」ボタン |
| `blm_mobile_session_v1` | iPhoneモードで作業途中の選択済み図書リストと移動先設定 | 無期限（手動消去まで） | iPhoneモード上部の「🧹 端末内の作業途中データを消去」ボタン |
| `blm_change_history_v1` | 変更反映時の履歴と更新前スナップショット | 無期限（手動消去まで） | 「🗑️ ブラウザ内保存データを全消去」ボタン |

### バックアップと復元の手順
1. **変更履歴からの直前スナップショット復元**
   * PC台帳管理モードの「🕒 5. 変更履歴・バックアップと復元」タブを開きます。
   * 変更履歴ログの各行にある **「⏪ この変更前の状態に戻す」** をクリックすると、その変更を適用する直前の蔵書台帳へ即座に復元されます。
2. **ファイルによる全体バックアップと復元**
   * **バックアップ保存**: 同タブの **「💾 全体バックアップファイル保存 (JSON)」** をクリックすると、現在の台帳・作業途中リスト・変更履歴をまとめた `book_location_backup_YYYYMMDD.json` がPCに保存されます。
   * **バックアップからの復元**: **「📂 バックアップファイルから復元」** から保存済みのJSONファイルを選択すると、当時の状態が完全に復元されます。

## 3. 外部通信の一覧とデータ非送信の確認

本アプリケーションのソースコード（`index.html`, `js/core_logic.js`, `js/qrcode_mini.js`, `js/app.js`, `js/demo_data.js`）およびPythonスクリプトにおける外部通信の実装状況は以下のとおりです。

### A. 業務データの外部送信：なし（0件）
* 蔵書リスト、カメラ映像、撮影した奥付画像、OCR認識テキスト、選択履歴、箱管理番号、QRコードデータについて、外部サーバーやクラウドAPIへ送信（POST / PUT / WebSocket / ビーコン送信等）するコードは**一切存在しません**。
* アクセス解析（Google Analytics等）、エラー収集サービス、外部フォント読込、外部QRコード生成APIも一切使用していません（QRコードは `js/qrcode_mini.js` によりブラウザ内のCanvas計算のみで完結します）。

### B. ライブラリおよびOCR言語データの取得通信（受信のみ）
通常操作（デモデータ閲覧、CSV入出力、模擬OCR検証、手動検索、QRコード生成・読取、別紙2-3出力）では、**外部通信は一切発生しません（完全オフライン動作）**。

唯一、iPhoneモードで **「実機カメラ連続読取」または「奥付写真ファイルからのブラウザ内OCR」を実行した際のみ**、ブラウザ内OCRエンジン（Tesseract.js WebAssembly版）を取得するために以下のCDNへのGET通信（受信のみ）が発生します。

| 通信発生タイミング | 通信先URL（ドメイン） | メソッド / 方向 | 送受信内容 | 業務データの送信有無 |
| :--- | :--- | :---: | :--- | :---: |
| 通常起動・検索・模擬OCR・CSV入出力・QR表示 | **通信なし（ローカル完結）** | - | - | **なし** |
| 実機カメラOCR／写真OCRの初回実行時のみ | `https://cdn.jsdelivr.net/npm/tesseract.js@5/...` | `GET`（受信のみ） | Tesseract.js プログラム本体およびWebAssemblyバイナリの取得 | **なし**（画像の送信は行われず、取得したWASMにより端末メモリ内でOCR処理） |
| 実機カメラOCR／写真OCRの初回実行時のみ | `https://tessdata.projectnaptha.com/4.0.0/jpn.traineddata.gz` （Tesseract.js標準の言語データ取得先） | `GET`（受信のみ） | 日本語・英語のOCR辞書データ（`traineddata`）のダウンロード | **なし** |

> **※社内閉域網などで上記CDNへのGET通信も遮断したい場合**: `tesseract.min.js` と `jpn.traineddata.gz` をフォルダ内にローカル配置し、`js/app.js` の `ensureTesseractLoaded()` 内のパスをローカル相対パスに変更することで、100%外部通信ゼロにすることも可能です。
